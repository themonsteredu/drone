# 항공모빌리티 진로기록 제출

## 학생 사용 순서

1. 모아허브의 열린 학생 수업 보드에서 항공모빌리티 웹앱을 엽니다.
2. 항로와 선택 이유를 정하고 출발 점검 후 의약품 운송 또는 재난 탐색 임무를 수행합니다.
3. 결과 화면에서 이름/모둠과 다음 운항에서 바꿔볼 점을 입력합니다.
4. **진로기록에 제출**을 누릅니다. 서버가 저장을 확인한 경우에만 접수번호와 **제출 완료**가 표시됩니다.

성공한 임무와 시간 초과로 끝난 임무 모두 활동 기록을 제출할 수 있습니다. 교사 점검 모드, 진행 중인 임무, 학생·수업 정보 없이 직접 연 앱에서는 온라인 제출을 할 수 없습니다. 기존 HTML 기록 파일 저장·공유는 사용할 수 있습니다.

## 연결 규격

| 구간 | 규격 |
|---|---|
| 학생 입장 | Hub가 기존 브라우저 학생 UUID를 `student_id`, 수업 코드를 `hub_code` 쿼리로 전달 |
| 제출 주소 | `POST https://hub.moakit.ai/api/career-log/ingest` |
| 프로그램 | `aviation-mobility-01` |
| 제출 본문 | `board_code`, `student_id`, `program_ref`, `source_event_id`, `process`, `artifact`, `reflection`, `raw_data` |
| 시도 식별자 | 임무를 새로 시작할 때 생성한 UUID를 종료까지 유지 |
| 중복 방지 키 | `aviation-mobility-01:<boardCode>:<studentId>:<attemptId>` |
| 상세 기록 | `raw_data.activity = aviation-flight`, `raw_data.record = MissionActivityRecord v1` |
| 저장 확인 | HTTP 성공 + `ok: true`, 유효한 `record_id`, 요청과 같은 `student_id`, boolean `duplicate` |

`process`는 항로·선택 이유, `artifact`는 임무 상태·점수·충돌·이탈 요약, `reflection`은 학생의 돌아보기입니다. 상세 기록에는 점검, 시간, 배터리, 화물 인계, 탐색 결과와 평가를 함께 담습니다.

Hub 서버가 열린 보드·공개 프로그램·해당 보드에 배정된 드론 링크를 확인하고 실제 보드 ID로 `session_ref`를 생성합니다. 드론에는 Supabase 키나 DB 접속 정보를 넣지 않습니다. 학생 연결은 기존 Hub의 브라우저 UUID 방식이며 로그인 계정 인증이나 실제 조종 인증을 뜻하지 않습니다. 서버 기록의 검증 필드는 `null`입니다.

## 실패와 복구

- 첫 제출 본문을 고정한 뒤 전송합니다. 실패 후 재시도는 같은 내용과 같은 식별자를 사용합니다.
- 미전송 본문은 학생·보드별 `sessionStorage`에 임시 보관합니다. 같은 탭에서 새로고침하면 첫 화면의 **미전송 운항 기록 → 다시 제출**로 복구합니다. 탭을 닫은 뒤의 보관은 보장하지 않습니다.
- 이전 미전송 기록을 새 임무가 덮어쓰지 않습니다. 현재 미전송 기록을 먼저 제출해야 합니다.
- 브라우저 임시 보관이 차단되면 실제 저장 실패를 안내하고 열린 화면에서 재시도합니다.
- 서버 확인 없이 `제출 완료`를 보관하거나 표시하지 않습니다. 응답이 유실된 경우 서버에서 기존 기록의 같은 접수번호를 돌려줍니다.
- 온라인 제출 후에는 해당 시도의 입력을 고정합니다. 파일 내보내기도 같은 제출 내용을 사용합니다.

## 운영 반영

이 코드는 배포 준비 상태입니다. 드론 프런트엔드만 배포해서는 온라인 제출이 연결되지 않습니다.

1. `themonsteredu/teacher-s-project`의 항공모빌리티 연동 변경에 포함된 Supabase `career-log-ingest` 함수를 먼저 반영합니다.
2. 같은 Hub 변경의 API 허용 목록·기록 검증·학생 링크 연결을 배포합니다.
3. 이 드론 변경을 배포합니다.
4. 사용할 프로그램에 드론 운영 URL `https://drone-six-smoky.vercel.app`을 **웹앱** 자료로 등록하고, 학생 보드의 오늘 수업자료에 배정합니다. 사이트·프로그램·보드 공개 상태도 확인합니다.
5. 실제 수업 보드에서 실물 조종기로 결과까지 진행한 뒤 제출과 접수번호를 확인합니다.

함수 코드, 동시 제출 처리와 배포 순서의 세부 내용은 Hub 저장소의 `docs/aviation-career-log.md`를 따릅니다. DB 테이블 추가·변경은 필요하지 않습니다.

자동 검사에서는 학생/수업 연결, 기존 임무 동작, 제출 본문, 중복 클릭, 실패 후 같은 본문으로 재시도, 새로고침 복구, 잘못된 저장 응답과 교사 점검 차단을 확인합니다. 실물 조종기부터 운영 DB 저장까지의 실서비스 검증은 별도입니다.
